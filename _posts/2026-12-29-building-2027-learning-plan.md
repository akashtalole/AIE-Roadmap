## Starting From Self-Assessment, Not a Generic Checklist

```python
def assess_current_state(completed_capstones: list[str], comfort_levels: dict) -> dict:
    return {
        "strong_areas": [area for area, level in comfort_levels.items() if level >= 4],
        "growth_areas": [area for area, level in comfort_levels.items() if level < 3],
        "capstones_completed": completed_capstones,
    }
```

Your own honest assessment of which of this roadmap's ten months you engaged with deeply versus skimmed is the right starting point for a personal plan — a generic "learn everything" plan is exactly the unsustainable approach December 22 warned against.

## A Concrete Quarterly Structure

```python
quarterly_plan_template = {
    "q1_2027": {"focus": "pick 1-2 growth areas from self-assessment", "deliverable": "a capstone-style project applying them"},
    "q2_2027": {"focus": "deepen production practices in an area you're already using at work", "deliverable": "a case study, per Dec 20's format"},
    "q3_2027": {"focus": "revisit this roadmap's content against how the field has actually evolved (per Dec 28)", "deliverable": "an updated personal knowledge base entry"},
    "q4_2027": {"focus": "consolidate and reflect — your own year-in-review, mirroring yesterday's post", "deliverable": "a retrospective write-up"},
}
```

Quarterly, not monthly, planning matches a more sustainable cadence than this roadmap's own daily pace — this roadmap was an unusually intensive reference resource to work through; your ongoing personal learning plan should be paced for genuine sustainability over the following year.

## Balancing Breadth and Depth

```python
def balance_plan(available_hours_per_month: float) -> dict:
    return {
        "deep_focus_area": available_hours_per_month * 0.6,  # one or two areas, genuinely mastered
        "breadth_maintenance": available_hours_per_month * 0.3,  # December 22's tiered-attention practice
        "buffer_for_opportunistic_learning": available_hours_per_month * 0.1,  # something unplanned that turns out to matter
    }
```

## Setting Genuine, Checkable Milestones

```python
def define_milestone(goal: str, target_date: date, success_criteria: list[str]) -> dict:
    return {"goal": goal, "target_date": target_date, "success_criteria": success_criteria, "status": "not_started"}
```

Vague intentions ("learn more about agents") rarely survive contact with a busy year — specific, checkable milestones with target dates, following exactly November 16's spec-writing discipline applied to a personal learning goal, are what actually get accomplished.

## Reviewing and Adjusting the Plan

```python
def quarterly_plan_review(plan: dict, actual_progress: dict) -> dict:
    return {"on_track": actual_progress["completed"] >= plan["planned"] * 0.7, "adjustment_needed": actual_progress["completed"] < plan["planned"] * 0.5}
```

A learning plan is itself something to iterate on — the same continuous-improvement discipline this roadmap has applied to every technical system, applied reflexively to your own professional development plan.
